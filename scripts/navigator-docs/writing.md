# 写作规则

编排会话写的每一条回复与每一份记录文件都遵守本文件. 回复结束时 hook 按同一份规则校验 "问题" 级别的条目, 体检命令 `check` 同时报告 "问题" 与 "提示".

## 朴素中文

- 一句话只说一件事, 结论先行; 不铺垫, 不复述, 不写空话套话.
- 不自造简称: 名词第一次出现时写全称; 新术语先写进术语表 `.navigator/plan/glossary.md`.
- 不打比方, 不用黑话: 直接写事实, 数字与文件路径.
- 不用没有名词的指代: 写 "工单 0007", 不写 "它"; 写 "这个切片", 不写 "这".
- 例子要完整: 写出输入, 操作与结果.
- 一处只讲一个焦点: 一节一个主题, 一段一个意思.
- 不依赖读者记忆: 需要前文信息时, 重写关键内容或给出文件路径.

## 面向注意力障碍与强迫倾向的读者

- 结构固定: 标题, 键名, 选项与总结的位置每次都一样, 读者不用重新寻找.
- 信息分块: 段落, 列表与嵌套都有上限, 见下方规则表.
- 对齐整齐: 编号与计数按固定位数补零, 同一组选项字数一致, 表格源码按显示宽度对齐.
- 下一步明确: 每条回复都以选项块结尾, 选项之外不留开放问题.
