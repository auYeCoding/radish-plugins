# review

[English](review.en.md) | 简体中文

[返回 TracePoint](../README.md)

遇到问题时调用: 代理先把本会话里遇到的问题按事实写出来供你核实, 并记成缺陷; 再汇总全部缺陷记录, 把反复出现的归因后交你决定是否迭代技能. 本技能只呈现事实与建议, **不自行改任何技能** — 改技能由你批准.

## 适用场景

- 用 `analyze` 或 `protected-code` 时结果不对, 卡住, 或照规则做却行不通, 想让代理把当时的情形说清楚, 方便你核实是不是技能的问题.
- 想看之前记下的缺陷里哪些反复出现, 值得改进技能或规则.

## 触发方式

**只能斜杠调用:** `/tracepoint:review`. 本技能不自动触发. 可以在命令后附一句说明指出是哪件事, 例如 `/tracepoint:review 刚才重复分析了同一个函数`.

缺陷记录有两个来源: 你纠正时, 插件 hook 会提示代理当场往 `.tracepoint/defects/` 追加一条; 你调用本技能时, 代理为本会话的问题补记. 两者都只记事实 (看到什么, 依据哪条规则, 做了什么, 结果如何). 代理不下 "是规则错还是自己错" 的结论 — 那不可靠, 归因留到复查时由人按固定分类表做.

## 使用流程

1. **说清本会话遇到的问题.** 代理回顾本会话, 对每个问题写出: 用的哪个技能与任务, 当时看到什么, 依据技能里哪条规则 (引原文), 做了什么, 结果与你的期望差在哪. 只写事实, 记不清的写 "记不清". 本会话没有这类问题时会直接说明.
2. **记成缺陷记录.** 每个问题存成 `.tracepoint/defects/` 下的一个 JSON 文件; 同一类问题沿用已有的模式键. 你指出描述不准时, 代理改正描述并同步改记录.
3. **汇总.** 运行 `review-defects.mjs` (技能会给出完整命令), 按模式键去重计数, 逐条列出每条记录的事实, 并标出达到提升阈值 (默认复现 >=3, 跨 >=2 个任务, 30 天内) 的模式. 代理把这些事实转述给你, 不只报条数.
4. **按固定分类表归因.** 每个达阈值的模式选一类: 规则没覆盖 / 技能或 hook 没触发到 / 规则丢了 / 规则有歧义 / 规则在但没遵守 / 不是技能能解决的.
5. **提给你决定.** 按类别给出改法建议 (改规则, 下沉到 hook/校验器, 或记为已知限制), 你批准后才改.

## 已知限制

- 第 1 步的描述来自代理对本会话的回顾, 可能有遗漏或记错, 所以要你核实; 会话被压缩后细节更容易丢, 遇到问题时尽早调用.
- 阈值以下的模式只呈现事实, 不主动提请改动, 避免把偶发当成规律; 你明确要求时仍可就单个问题讨论改法.
- 目录里没有 `.tracepoint/` 案卷时不会新建, 问题只在回复里描述, 不存档.
- 只处理 TracePoint 自己命名空间下的技能; 其它插件 (如 WayPoint) 用各自的 `/<插件>:review` 复查, 互不重复.
- 改技能必须由你批准, 本技能不会自行修改 `SKILL.md`.
