# review

[English](review.en.md) | 简体中文

[返回 TracePoint](../README.md)

复查 TracePoint 使用中记下的技能缺陷, 把反复出现的归因后交你决定是否迭代技能. 本技能只呈现事实与建议, **不自行改任何技能** — 改技能由你批准.

## 适用场景

- 你在用 `analyze` 或 `protected-code` 时纠正过它的结果, 插件 hook 提示记下了缺陷, 想定期复查.
- 想看哪些缺陷反复出现, 值得改进技能或规则.

## 触发方式

**只能斜杠调用:** `/tracepoint:review`. 本技能不自动触发.

缺陷怎么来的: 你纠正时, 插件 hook 会提示代理往 `.tracepoint/defects/` 追加一条只含事实的记录 (看到什么, 依据哪条规则, 做了什么, 结果如何). 代理不下 "是规则错还是自己错" 的结论 — 那不可靠, 归因留到复查时由人按固定分类表做.

## 使用流程

1. **汇总.** 运行 `review-defects.mjs` (技能会给出完整命令), 按模式键去重计数, 列出达到提升阈值 (默认复现 >=3, 跨 >=2 个任务, 30 天内) 的模式. 未达阈值的不提请改技能.
2. **读记录.** 对每个达阈值的模式, 读 `.tracepoint/defects/` 下的原文看清事实.
3. **按固定分类表归因.** 每个模式选一类: 规则没覆盖 / 技能或 hook 没触发到 / 规则丢了 / 规则有歧义 / 规则在但没遵守 / 不是技能能解决的.
4. **提给你决定.** 按类别给出改法建议 (改规则, 下沉到 hook/校验器, 或记为已知限制), 你批准后才改.

## 已知限制

- 阈值以下的模式不提请改动, 避免把偶发当成规律; 它们留着继续累积.
- 只处理 TracePoint 自己命名空间下的技能; 其它插件 (如 WayPoint) 用各自的 `/<插件>:review` 复查, 互不重复.
- 改技能必须由你批准, 本技能不会自行修改 `SKILL.md`.
