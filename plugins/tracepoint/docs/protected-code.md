# protected-code

[English](protected-code.en.md) | 简体中文

[返回 TracePoint](../README.md)

分析带保护或混淆的编译代码的通用方法. 先识别保护属于哪一类, 再决定走静态还是动态, 不对着保护硬啃静态. 本技能只讲一般方法与思路, 不写针对任何具体产品的绕过步骤; 并诚实说明模型能做与不能做的部分.

## 适用场景

目标抵抗常规分析时, 与 [analyze](analyze.md) 一起用:

- 加壳或运行时解密的代码; 反调试; 自修改代码.
- 控制流平坦化; 不透明谓词; 虚假控制流.
- 自定义字节码虚拟机 (VM); 诱饵与误导性构造.

## 触发方式

**自然语言:** 例如 "这个程序像加了壳, 怎么分析", "这段控制流被平坦化了".

**斜杠命令:** `/tracepoint:protected-code`. 分析停滞或看起来被混淆时也会自动参与.

## 方法概要

1. **先识别保护类型.** 分三类: 隐藏类 (加壳, 运行时解密, 自修改), 复杂化类 (控制流平坦化, 不透明谓词, 自定义 VM), 误导类 (诱饵, 假符号, 假成功条件). 识别错会浪费大量静态精力.
2. **据类型选路径.**
   - 隐藏类: 多走动态 — dump 脱壳后的内存, patch 掉反调试, 让目标自己把真实代码/状态暴露出来.
   - 复杂化类: 提取字节码按 opcode 表解码, 或还原控制骨架; 自定义 VM 优先把分发循环当解释器, 真实逻辑在数据 (字节码) 里, 不要把 switch 分支逐条当算法步骤.
   - 误导类: 用环境里的真值核对, 不被假符号与诱饵带偏.
3. **诚实标注做不到的部分.** VM handler 的完整静态语义还原对当前模型普遍很难; 做不到就明说 "需要动态执行才能确定", 不编造等价逻辑.

## 模型能做与不能做

- **能做:** 识别保护类别并选对路径; 小规模字节码 VM 的静态解码与等价式还原; 指出哪里需要转动态.
- **常做不到:** 大规模或嵌套 VM 的完整静态去虚拟化; 强对抗下不借助动态执行的完整还原. 这些场景应转动态, 或诚实交回部分结果.

## 已知限制

- 只给通用方法与思路, 不针对任何具体加壳/反作弊产品给绕过步骤.
- 动态手段 (调试器, 插桩, dump) 需要对应工具处于可连状态, 并在你授权的目标上进行.
