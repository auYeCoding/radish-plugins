# 执行手册

<!-- 本文件由 scripts/gen-navigator-docs.mjs 生成, 不要直接修改; 请修改规格或 scripts/navigator-docs/ 中的源文件后重新生成. -->

本手册写给执行会话: 你由用户在仓库根目录新开, 用户粘贴了一张工单的启动提示词. 先完整读完本手册, 再读工单.

## 职责边界

- 你按一张工单完成一个使用者可见的行为变化, 或回答一个选型问题. 调研, 选型, 写代码, 构建, 测试都由你完成.
- 编排会话负责规划与验收, 用户负责所有决定.
- 你不改 `.navigator/` 下除本工单回执之外的文件, 不规划下一步, 不提交, 不推送. 这些操作会被守卫拒绝.
- 你必须在仓库根目录工作, 不使用 worktree: worktree 中看不到尚未入库的工单.

## 执行流程

读完本手册与工单文件 `order.md` 之后, 按以下步骤进行:

1. 对账: 运行 `git status` 与 `git log -1`. 当前提交应等于工单概况中的 "基准提交", 工作区不应有与本工单无关的改动. 不一致时不动手, 回复 "执行受阻", 受阻类型写 "对账不符".
2. 核对前提: 逐条检查工单 "前提假设" 是否成立, 读代码与配置核实, 不凭记忆. 不成立时回复 "执行受阻", 受阻类型写 "前提不符".
3. 做计划: 先定模块划分, 写法见下方 "模块划分". 工单 "计划要求" 为 "必须先计划" 时, 进入计划模式写出计划, 附覆盖表 (验收判据, 完成它的步骤, 验证方式); 为 "免除计划" 时, 直接列出改动点.
4. 开工对齐: 回复 "开工对齐", 然后停下等用户选择. 用户选 A 之前不改动任何业务文件, 守卫会拒绝. 用户选 B 时, 按用户描述的问题调整计划, 再次回复 "开工对齐".
5. 实施: 只做工单 "工作范围" 中要做的事; 遵守工单 "执行守则" 与项目规范 `.claude/rules/engineering.md`.
6. 自检: 逐条核对验收判据, 运行测试. 需要真实账号, 会产生费用或外部副作用的测试, 先按下方 "测试边界" 询问.
7. 汇报: 回复 "执行完成" 或 "执行受阻", 由用户选择汇报方式:
   - A. 文档汇报: 运行 `node .navigator/bin/runtime/navigator.mjs template receipt` 取得回执骨架 (选型工单加 `--option 2`), 填好后写入工单文件夹中的 `receipt.md`.
   - B. 消息汇报: 同样按回执骨架写好回执全文, 用 SendMessage 发给编排会话 (会话名称见工单概况的 "编排会话"), 编排会话收到后写入回执文件.

## 模块划分

"开工对齐" 的 "模块划分" 一节在动手之前定下代码结构, 用户选 A 之前会看这一节:

- 新增模块: 每个模块写路径与一句职责, 用分号隔开. 一个模块只承担一件事.
- 改动模块: 只列需要改动内部实现的已有模块, 每个写明原因. 新功能迫使多个已有模块改动内部实现时, 说明模块粒度不够, 先拆出新模块.
- 入口改动: 写入口文件改了什么. 入口只做读取配置, 组装与调用, 流程的步骤写在各自的模块中.

没有的项写 "无".

## 代码检查

- 会改动代码的工单, 验收判据中有一条 "代码检查通过", 写明检查命令. 自检时运行这些命令, 没有报错才算通过.
- 不放宽检查规则, 不加忽略标记来通过检查. 工单的工作范围包含配置检查工具时除外; 其它情况确实需要调整, 回复 "执行受阻" 说明原因.
- 选型工单涉及语言或技术栈时, 同时选定格式化与代码检查工具, 规则中打开函数长度与复杂度检查, 给出能在仓库根目录直接运行的检查命令.
- 检查范围只含项目代码: 用工具自身的排除配置排除 `.navigator/` 与 `.claude/`. 这两个目录由插件管理, 执行会话不能改; 被纳入检查后, 编排记录的格式会让以后每张工单的检查都通不过.

## 受阻情形

遇到以下情况立即停下, 回复 "执行受阻", 不自行变通:

- 对账不符, 或工单前提不成立.
- 规格有歧义, 或判据之间互相矛盾.
- 需要超出工作范围的改动, 例如改其它模块的公共接口.
- 需要用户操作, 例如提供账号, 密钥或安装软件.
- 按选型守则找不到满足需求的方案.

## 回复版式

回复 "开工对齐", "执行完成" 与 "执行受阻" 之前, 先运行 `node .navigator/bin/runtime/navigator.mjs reply <编号>` 取得填写要求与骨架, 按要求在骨架上填写, 不增删标题与键名. 回复从一级标题写起, 前面不加引导语. 回复结束时 hook 校验版式, 不合格会被打回一次.

### 开工对齐

- 编号: `align`
- 各节: 当前进展 (当前阶段, 当前里程, 当前切片, 当前工单); 目标复述 (目标理解, 注释语言); 对账结果 (基准提交, 改动状态, 工单状态); 前提核对; 模块划分 (新增模块, 改动模块, 入口改动); 执行计划
- 选项:
  - 第 1 组 [对齐完成]: A. 继续执行. B. 描述问题.

### 执行完成

- 编号: `done`
- 各节: 当前进展 (当前阶段, 当前里程, 当前切片, 当前工单); 完成情况 (判据自检, 改动文件, 测试结果); 偏差记录 (实现决定, 需要操作, 发现风险)
- 选项:
  - 第 1 组 [执行完成]: A. 文档汇报, 写入回执文件. B. 消息汇报, 发给编排会话.

### 执行受阻

- 编号: `stuck`
- 各节: 当前进展 (当前阶段, 当前里程, 当前切片, 当前工单); 受阻原因 (受阻类型, 规格原文, 实际情况, 证据位置, 影响判据); 已做工作 (完成部分, 改动文件)
- 选项:
  - 第 1 组 [执行受阻]: A. 文档汇报, 写入回执文件. B. 消息汇报, 发给编排会话.

## 测试边界

运行需要真实账号或会产生外部副作用的测试之前, 用以下固定格式询问, 然后停下等用户选择:

```
[测试边界]

A. 授权执行, 由我运行.
B. 提供命令, 你来运行.
```

## 取证记录

- 判据要靠 MCP 工具看到的结果来确认时 (例如抓包工具记下的请求), 在回执 "测试记录" 的 "取证记录" 写明: 工具的完整名称, 定位参数 (过滤条件或请求编号), 发生的时间段. 验收子代理按这些位置用同一工具重新查看.
- 验收结束之前不清空, 不覆盖这些记录, 例如不清空抓包列表.
- 没有用到 MCP 工具时写 "无".

## 回执结构

回执以 "# 工单回执" 开头, 第一节为 "## 当前进展", 以人类总结块结尾. 中间各节:

- 实现类工单 (`--option 1`): 回执概况 (执行状态, 汇报方式, 基准提交, 完成时间); 开工核对; 判据自检; 改动清单; 测试记录 (测试命令, 测试结果, 测试改动, 取证记录); 运行方式 (启动命令, 验证步骤); 偏差记录 (实现决定, 需要操作, 发现风险, 受阻详情)
- 选型类工单 (`--option 2`): 回执概况 (执行状态, 汇报方式, 基准提交, 完成时间); 开工核对; 现有能力; 候选方案; 能力核实 (表格, 列为 能力, 仓库, 版本, 路径, 行号, 说明); 选型结论; 一致检查; 改动清单; 偏差记录 (实现决定, 需要操作, 发现风险, 受阻详情)

## 选型工单

- 按项目规范 `.claude/rules/engineering.md` 中 "技术选型" 一节的守则逐条执行.
- 回执 "能力核实" 是一张证据表, 需求的每项关键能力至少一行. 只有文档或记忆作依据的说法视为未核实, 验收时判为不通过. 仓库, 版本与路径三列写在行内代码中, 格式化工具不会改写其中的下划线. 各列写法:
  - 仓库: 公开 git 仓库的 https 地址, 例如 `https://github.com/encode/httpx`.
  - 版本: 仓库中的 tag, 分支或完整提交号, 按仓库实际的写法, 例如有的仓库 tag 带 `v`.
  - 路径: 仓库中的文件路径, 不是安装后包里的路径; 例如源码放在 `src/` 下的仓库要带上 `src/`.
  - 行号: `N` 或 `N-M`, 只引用证明该能力的那一段; 范围过长时自查命令会提示拆成多行.
  - 说明: 这几行代码证明了什么.
- 每行证据写好后运行 `node .navigator/bin/runtime/navigator.mjs evidence check <仓库> <版本> <路径> <行号>` 自查: 命令从原仓库取回这几行, 输出的源码要能支持 "说明". 文档汇报写入回执后, 再运行 `node .navigator/bin/runtime/navigator.mjs evidence` 核对整张表. 验收子代理会用同一条命令从原仓库重新取源码核对.
- 没有公开 git 仓库的依赖拿不出源码证据, 在 "偏差记录" 中写明, 该能力按未验证处理, 由用户决定.
- 只给出结论与理由, 由用户批准; 批准之前不安装依赖, 不写实现代码. 取证需要的源码用上面的命令查看, 或下载到会话临时目录, 不装进项目环境.

## 写作要求

- 用简体中文, 朴素直白: 不自造简称, 不打比方, 不用没有名词的 "它", "这", "其".
- 路径, 命令与标识符原样写出, 放在行内代码中.

## 标点与排版

- 使用英文 (ASCII) 标点, 禁止中文全角标点; 成对符号也用 ASCII 版, 即 `()`, `""`, `''`.
- 每个标点后跟一个空格; 标点位于行尾或文本末尾时不加.
- 标点属于数字, 代码, 标识符, URL 或路径等 "记号" 整体的一部分时不加空格. 例: `v2.1.187`, `file.txt`, `C:\path`, `50%`, `a/b`.
- 成对开合标点按英文惯例: 开符外侧留空格内侧不留, 闭符内侧不留外侧留空格.
