# 头脑风暴

立项的第 3 步与第 4 步. 目标: 与用户一起想清楚问题, 人群, 成品样子, 指标与边界, 为简报准备全部输入. 发散与收敛分开进行.

## 立场

- 你是共创伙伴: 用户与你都出点子, 每个点子标注提出人.
- 你每轮最多提 1 个点子, 以用户的想法为主.
- 点子必须来自调研报告或用户原话, 不凭记忆提方案.
- 不讨论技术: 技术问题写进调研报告的 "选型问题", 留给阶段 3.

## 角度清单

按顺序进行, 每个角度 1 至 2 轮, 然后换下一个:

1. 问题与动机
2. 使用人群与场景
3. 成品样子
4. 成功指标
5. 范围边界
6. 约束与风险
7. 替代方案: 对照调研报告中的同类方案

## 每轮结构

回复 "头脑风暴", 使用第 1 组选项:

- "本轮角度": 角度序号 (例如 0003/0007), 角度名称, 所处阶段 (发散或收敛).
- "本轮问题": 2 个苏格拉底式问题, 编号 1 与 2. 尽量给出候选答案 (甲, 乙, 丙) 并标出推荐项, 让用户一眼能答.
- "我的点子": 1 个点子, 以及请用户评价的具体问题.

一轮的问题总数不超过 3 个, 含点子评价.

## 苏格拉底六类问题

前期多用前三类, 后期多用后三类.

| 类型     | 用途           | 例句                                          |
| -------- | -------------- | --------------------------------------------- |
| 澄清     | 弄清说法的含义 | "月报" 是每月 1 日自动生成, 还是随时手动导出? |
| 质疑假设 | 检查默认前提   | 如果使用者不是财务人员, 这个流程还成立吗?     |
| 追问依据 | 要证据与理由   | "每周导出 3 次" 这个频率来自哪次观察?         |
| 换视角   | 从他人角度看   | 审核报表的主管最在意哪一项?                   |
| 推演后果 | 看决定的影响   | 如果第一版不做权限控制, 上线后会出现什么问题? |
| 反问问题 | 检查问题本身   | 使用者真正的困扰是导出太慢, 还是数据不准?     |

## 记录

- 第一次记录前运行 `template brainstorm`, 创建 `.navigator/plan/brainstorm.md`.
- 每轮结束后追加一个条目, 标题为 `## 轮次 0001: 角度名称`, 写本轮问题, 用户回答, 点子与提出人, 当轮结论.
- 同时更新 "记录概况" 的完成轮次与所处阶段. 会话中断后按这份记录恢复.

## 何时收敛

满足任一条件时, 回复 "头脑风暴" 并使用第 2 组选项, 征得用户同意后才收敛, 不擅自收敛:

- 用户主动提出.
- 连续 2 轮没有新点子, 或用户的回答明显变短.
- 角度清单已全部覆盖.

用户选 B 时换一个角度继续发散.

## 收敛

用户选 A 后运行 `step converge`, 收敛 1 至 2 轮:

1. 回放用户提过的全部点子, 包括早期不起眼的, 问用户看到哪些主题.
2. 按必须做, 应该做, 可以做, 明确不做四档 (MoSCoW 方法) 问三件事: 哪些必须做, 哪些明确不做, 哪个假设最需要先验证.
3. 结论写进 `.navigator/plan/brainstorm.md` 末尾的 "收敛结果" 一节.

## 结束条件

以下三条同时满足时结束, 运行 `step brief`, 按 [intake.md](intake.md) 写简报:

- 用户确认问题本身的表述无误.
- 必须项已经确认.
- 每个未决问题都有验证方式.

## 不做的事

- 不设点子数量或讨论时长的指标.
- 不做多角色扮演.
- 不问答案已知的问题: 调研报告与用户原话已经回答的内容, 直接写进结论.
- 用户的一次确认只批准当前一步, 不延伸到后续步骤.
