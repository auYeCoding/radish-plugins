# 恢复与异常

## 恢复进度

新会话调用技能时, 新会话接管编排, 原编排会话不能再写编排记录. "下一动作" 要求回复 "恢复进度" 时:

- "上次位置": 最后动作与记录时间, 取自 "当前状态".
- "期间变化": 对账结果, 新增提交 (差异提交), 新增回执 (工单状态一行).
- "后续操作": 接着要做的一件事.

用户选 A 后运行 `status`, 按其中的下一动作继续.

## 验收异常

"下一动作" 要求回复 "验收异常" 时, 其它命令都已暂停, 只能运行 `restore`, `adopt`, `snapshots` 与 `status`.

| 对账结果           | 含义                                                                                              | 选项组  |
| ------------------ | ------------------------------------------------------------------------------------------------- | ------- |
| 发生回退           | 当前提交早于记录中的提交                                                                          | 第 1 组 |
| 历史分叉           | 切换了分支, 或提交历史被改写                                                                      | 第 1 组 |
| 陌生提交           | 记录之后出现了不经过编排的提交                                                                    | 第 2 组 |
| squash 合并        | 分支被 squash 合并, 记录内容一致                                                                  | 第 2 组 |
| 状态目录与快照不符 | 记录文件被手工改动, 或被 git 回退 (例如回到上一次提交, 丢掉了之后的记录); "改动文件" 列出具体文件 | 第 3 组 |

记录与快照不符时, 改变编排状态的命令都会拒绝运行, 拒绝理由列出改动的文件; 这时运行 `status`, 按下一动作回复 "验收异常".

1. "对账结果" 四项取自 "当前状态"; "影响范围" 写涉及的工单, 涉及的切片与可用快照.
2. 用户选择后, 运行 "下一动作" 中写明的命令.
3. 第 1 组选 B: 等用户自行处理 Git, 再重新调用技能.
4. 第 2 组选 A: 运行 `adopt` 之后读差异提交的改动; 改动影响推进路线或决策时, 走需求变更.
5. 处理完后运行 `status`, 确认对账结果为 "一致".

## 运行受阻

编排会话自己的操作失败时 (命令被拒绝, 脚本出错, 环境问题), 不换写法绕开, 回复 "运行受阻":

- "受阻情况": 受阻操作, 受阻原因, 原始提示 (原样摘录一行), 影响范围.
- "处理办法": 用户需要做什么.

守卫的拒绝理由就是正确做法, 按拒绝理由调整, 不重试同一操作.

## 编排被接管

另一个会话调用本技能时, 编排由那个会话接管, 本会话收到提醒 "本会话已不是编排会话"; 写编排记录与运行改变编排状态的命令都会被拒绝. 这时不再推进编排, 回复 "运行受阻": "受阻原因" 写编排已被接管, "处理办法" 写 "要在本会话继续编排, 重新调用 /waypoint:project-navigator 接管; 否则回到接管的会话继续". 身份登记在本机的 Git 目录中, 回退或恢复记录不会改变身份.

## 状态文件损坏

"当前状态" 显示状态文件损坏时, 回复 "运行受阻". 用户同意后运行 `snapshots` 查看快照, 再运行 `restore <快照>`.

## 升级

"下一动作" 提示项目中的运行脚本较旧时, 回复 "初始设置" 第 1 组选项. 用户选 A 后按 SKILL.md 的 "初始设置" 重新运行 init 并完成自检. 升级只替换运行脚本与执行手册, 记录保留.
