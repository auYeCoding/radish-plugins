# 恢复与异常

## 恢复进度

调用技能时, 已有进度的项目先回复 "恢复进度". 任何会话调用技能都按记录中的状态继续, 不需要接管或登记.

- "上次位置": 最后动作与记录时间, 取自 "当前状态".
- "当前情况": 工单状态取自 "工单状态" 一行 (没有工单时写 "无"); 工作区域取自 "工作区域" 一行.
- "后续操作": 接着要做的一件事.

用户选 A 后运行 `status`, 按其中的下一动作继续. 有执行子代理还在工作时, 它属于启动它的会话; 在新会话中继续时, 按 "工单状态" 判断: 回执已写入就照常处理, 没有写入且原会话已经关闭时, 运行 `exec-brief` 重新派出执行子代理.

## 运行受阻

编排会话自己的操作失败时 (命令出错, 环境问题), 不换写法绕开, 回复 "运行受阻":

- "受阻情况": 受阻操作, 受阻原因, 原始提示 (原样摘录一行), 影响范围.
- "处理办法": 用户需要做什么.

守卫的拒绝理由就是正确做法: 编排会话写 `.navigator/` 之外的文件被拒时, 改为发布工单交给执行子代理.

## 问题报告

"运行受阻" 用于环境与操作的问题; 问题出在技能自身时, 回复 "问题报告", 用户会把报告转交给技能的维护者. 两种来源:

- 脚本发现: 命令输出或 `status` 中出现 "技能异常" 一行. 脚本会记下命令与 hook 的内部错误, 不自洽的状态, 被拒绝的 "下一动作", 以及状态不变时重复给出的 "下一动作".
- 你自己发现: 规则互相矛盾, 骨架与校验对不上, 照 "下一动作" 做却走不通, 子代理交回中写了 "技能问题".

做法:

1. 用 Write 把经过写成 `.navigator/drafts/` 下的 JSON 草稿: `{"doing": "当时在做什么", "expected": "预期发生什么", "actual": "实际发生了什么", "reproduce": "怎么复现"}`. 流程无法继续时加 `"blocked": true`.
2. 草稿只写遇到的情况本身: 做了什么, 看到了什么, 原始提示原样摘录. 不写原因推测, 不写处理建议, 不写修复方案; 不贴工单正文与业务代码.
3. 运行 `project-navigator report --from <草稿>`. 脚本补上环境, 状态与异常记录, 把报告写入 `.navigator/drafts/reports/`, 并输出报告全文.
4. 按输出的下一动作回复 "问题报告": "报告概况" 两项照抄输出; "报告内容" 放一个语言标记为 `text` 的代码块, 把报告全文原样放进去, 不增删内容.

"能否继续" 由脚本判断: 命令内部错误, 状态不自洽, 或草稿写了 `"blocked": true` 时为不能, 使用第 2 组选项, 等用户处理后再继续; 其余情况使用第 1 组选项, 用户选 A 后运行 `status`, 按其中的下一动作继续. 同一个问题只上报一次.

## 记录被回退或改动

记录都在 git 中. 用户用 git 回退了记录, 或手工改了记录文件时, 运行 `status`, 按当前记录继续; 状态与实际情况对不上时 (例如工单状态已回退, 代码却还在), 回复 "运行受阻", 说明对不上的地方, 请用户决定以哪边为准.

## 状态文件损坏

"当前状态" 显示状态文件损坏时, 回复 "运行受阻", 请用户用 git 恢复 `.navigator/state.json` (例如 `git checkout -- .navigator/state.json`) 后重新调用技能.

## 升级

"下一动作" 提示项目由旧版本初始化时, 回复 "初始设置" 第 1 组选项. 用户选 A 后运行 `project-navigator init`. 升级会移除项目配置中的旧 hook 与旧放行规则, 删除 `.navigator/bin/` 与 `.navigator/guide/` 下的副本, 清理旧的会话登记与快照; 编排记录全部保留. 已发布但还没有回执的工单撤回为起草中, 重新审阅后由执行子代理处理. 按 init 的输出提交改动.
