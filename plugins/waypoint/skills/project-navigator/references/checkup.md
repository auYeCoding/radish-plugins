# 体检

体检检查记录文件是否冗长, 是否好懂, 是否对注意力障碍与强迫倾向的读者友好. 调用参数为 `check`, 用户要求体检, 或里程复查时进行.

## 步骤

1. 脚本检查: 运行 `check`. 默认检查计划目录, 全部工单与验收记录, 以及最近一份回执; 也可以在命令后列出文件路径. 输出含体检编号, 问题清单与分类统计.
2. 语义检查: 派 `waypoint:navigator-reader`, 列出要检查的文件, 要求按下方评分表逐条检查. 每个问题交回文件, 行号, 类别, 原文摘录与说明.
3. 回复 "体检报告":
   - "体检范围": 文件数量, 脚本检查的问题数, 语义检查的问题数.
   - "问题清单": 表格, 列为文件, 位置, 类别, 说明. 问题级别在前, 提示级别只写数量.
   - "分类统计": 表格, 列为类别, 问题, 提示.
4. 在 `.navigator/plan/checkups.md` 追加条目 `## 体检 0001: 检查范围`, 编号取自脚本输出, 写体检时间, 检查范围, 问题数量与处理方式. 第一次写入前运行 `template checkups`.
5. 用户选 A: 逐条修正编排会话自己写的文档, 回执只报告不改; 修正后再运行一次 `check` 确认. 用户选 B: 只记录.

## 语义评分表

| 类别       | 检查什么                     | 反例                   |
| ---------- | ---------------------------- | ---------------------- |
| 自造简称   | 没有定义就使用的缩写         | 用 "NS" 代指导航状态   |
| 未定义术语 | 术语表中没有, 正文也没有解释 | 直接写 "热路径"        |
| 比喻       | 用比方代替事实               | "工单是一座桥"         |
| 指代不明   | 读者要往前找才知道说的是谁   | "失败后它会重试"       |
| 例子不完整 | 缺少输入, 操作或结果         | "像上次那样导出"       |
| 复述铺垫   | 重复前文或写开场白           | "如前所述"             |
| 空话套话   | 没有信息的句子               | "我们将持续优化体验"   |
| 一处多焦点 | 一段讲多件事                 | 一段话同时讲范围与风险 |
| 依赖记忆   | 需要读者记得早前的内容       | "按之前说的办"         |
